# dsh-yu-zhihu ｜ 刷知乎

谷时自己去知乎读东西，在限额内互动，把值得的经历交给人格素材入口。

---

## 它做什么

| 环节 | 具体做什么 |
|---|---|
| 读 | 按关键词和推荐流取内容，默认每天 40 条；每条读正文与评论 |
| 判 | 先把候选内容映射成内部 ID，再交给人格规划——外部文字不能直接变成发布动作 |
| 互动（可选） | 点赞、评论、回复、收藏、发想法，每轮都有硬上限 |
| 记 | 把值得的原句和判断写进 `voice.md` / `notes.md`，供人格蒸馏 |

---

## 安装

```powershell
dsh plugin --profile desktop add github:Speraymer/dsh-yu-zhihu
```

装完重启 DSH，设置里出现「刷知乎」。

---

## 第一次使用

1. **装 CLI 并登录**：这个插件通过 `zhihu` CLI 读写。装好后在设置页点「登录」，扫一次码；`cliPath` 留空时自动探测。
2. **先关互动**：把点赞/评论/回复/发帖先关掉，只读跑两轮，看它读到什么、怎么写。
3. **逐个打开**：确认语气像人，再一个一个开（建议顺序：点赞 → 收藏 → 评论 → 回复 → 发帖）。

## 运行机制

**跑一轮**：判断是否在谷时窗口 → 取内容（已读的不再取）→ 逐条读正文与评论 → 交给人格规划「这条要不要互动、怎么互动」→ 执行互动 → 记账（新增几条、互动成几条）→ 写日志。

**互斥**：上一轮没跑完时再点会直接返回「上一轮还在运行」，不会起两个进程。

**两道限额**：

1. **设置页的每轮条数**（点赞 6 / 评论 3 / 回复 3 / 收藏 3）—— 你可以调。
2. **代码里的硬上限**（12 / 6 / 6 / 6）—— 调设置也超不过去，防手滑。

**文字限额**：评论 ≤150 字，回复 ≤100 字；自主发帖标题 ≤200 字、正文 ≤3000 字。

**关系约束**：同一个人在同一条内容下最多回复两轮，由宿主过滤——不跟人拉锯。

**防注入**：候选内容的标题、正文、作者只作为数据进提示词；互动对象由宿主用内部 ID 决定，模型不能自己拼 URL。

## 边界与已知限制

- **峰时不跑**（谷时判断开着时）。想随时跑把「峰时」开关关掉。
- **需要 CLI 登录态**：凭证过期就整轮失败，日志里是 CLI 的原始错误。
- **互动是用你的号**：默认开着，第一次用建议先关，观察两轮。
- **限额有两套口径**：设置页那套是软的（可调），代码里那套是硬的（不可超）。改设置页不会突破硬上限。
- **读得多不等于记得住**：内容只有进了 `notes.md` / `voice.md` 才会影响人格。

---

## 依赖与降级

- 需要 `zhihu` CLI；没有时设置页会显示未就绪，跑一轮会直接失败并说明原因。
- 不依赖其他插件；缺兄弟插件照常工作。
- 没有模型权限时这一轮无法规划，会失败但不会写脏数据。
